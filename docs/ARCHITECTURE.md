# 客户端实现

运行路径：普通 HUD 的一个 `ImagePanel` → `UnlitGeneric` 材质 → 多帧 RGBA8888 VTF。面板覆盖整个视口，材质通过纹理坐标变换把图集中的当前姿势绘制到屏幕边缘。

Python 只在构建时工作。进入游戏后，由客户端原生材质代理计算时间、随机选择、姿势帧和位置，不需要服务器执行 Squirrel，也没有浏览器、DOM、联网服务或外部窗口。

## 构建模块

| 模块 | 职责 |
| --- | --- |
| `build_client.py` | 选择角色、生成图集、组合 HUD、写许可和构建清单 |
| `animation_assets.py`、`pose_layout.py` | 读取原动作帧，选择与重排客户端需要的姿势 |
| `texture_edges.py` | 仅修正 Evil 全透明像素的隐藏 RGB |
| `client_behavior.py` | 编译随机状态、五段运动和动画选择为 VMT 代理 |
| `hud_template.py` | 从本机游戏读取原版 HUD 模板 |
| `source_formats.py`、`read_vpk.py` | 写 VTF/VPK、读 VPK 并验证 CRC |
| `check_client_behavior.py`、`check_release.py` | 读取实际产物做行为与打包检查 |

## 随机状态

每段开始时采样路线、速度系数、停留时间、活动范围、目标地面位置、休息姿势、地面移动样式和小插曲。采样结果持有到本段结束，不会每次绘制都重新改变方向。

五个可复用运动阶段覆盖地面移动、墙上攀爬、顶部移动、松手跌落以及回到地面。下一段继承上一段的落点。原地休息保持在当前地面点，暂停绘制或地图时钟重置会触发适当的重启。

这是一套受材质预算约束的随机片段组合，不是通用 Shimeji 动作树。跌落用加速插值表现重力感，没有持续积分二维速度、阻力和碰撞。

## 纹理与预算

原单人图片通常为 128×128，统一放入 256×256 透明帧中；抱抱按自己的原锚点对齐。总图集 202 帧，RGBA8888，单 mip，约 50.5 MiB。VPK 文件体积较大主要来自未压缩的多帧图集，不应据此推断帧率或系统内存表现。

当前每包为一个面板、255 个代理、154 个自定义材质参数。开发中超过代理预算曾出现材质失效；更大的参数表也曾引起引擎崩溃。因此工具保守限制为 256 个代理、155 个自定义参数。155 是实测工作预算，不能写成 Valve 文档确认的通用上限。

Evil 的白边处理把附近轮廓颜色延伸到四个像素步长内的全透明 texel。全部 alpha 和非透明 RGBA 保持原样，完整材质与运动逻辑也保持原样；这是构建时的纹理准备，不是游戏运行时描边开关。

## 与参考项目的关系

web-mascot 提供灵感及其单独许可的素材包，没有移植 TypeScript 引擎。VSLib、SourceMod 示例和 Source SDK 2013 用于研究机制，没有进入客户端运行包。早期服务端 VScript 原型只保留在 `research/`，其事件与物理能力不能用于宣传当前客户端版。
